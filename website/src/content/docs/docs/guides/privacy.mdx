汇报、简报和挂断后的回复，都只在**你的电脑（daemon）**和**你的设备（App）**之间加密传输。server 只负责转发密文，没有密钥。

## 谁能看到什么

## server 会留下什么

| 内容 | 保留多久 |
|---|---|
| 待接听的来电 | 密文保存到某台设备接听、拒绝或「全部知悉」为止，然后删除 |
| 回复 | 排队期间保存密文，投递成功或失败后删除，只保留状态 |
| 推送记录 | 每台手机的推送令牌；每次推送和回执的时间、结果保留一天 |
| 通话历史 | 不保存，只在你的设备上 |

server 也不保存、不使用你的 Multica 令牌，令牌只在你电脑上的 daemon 里。

## 密钥从哪来

- **默认不用管**：daemon 第一次运行时随机生成一把密钥。同一台电脑上的桌面 App 会自动拿到它。
- **扫码加入的设备**：密钥跟着二维码从设备传到设备，server 看不到。
- **只输 6 位配对码的设备**：要再输一次加密口令。

## 自己设一个密钥

在「设置 → 加密」里填一句话，至少 12 个字符。每台设备填同一句话，就会得到同一把密钥。

- 本机 daemon 在线时，会一起换掉。
- 密钥不会经 server 改到别的电脑上，其他电脑要自己再填一次。

<Aside type="caution" title="换密钥之后">
- 用旧密钥加密、还没接听的来电就解不开了。
- 已经在本机历史里的记录不受影响，因为本地存的是解密后的内容。
- 解不开的来电不会响铃，空闲页会显示原因，可以「忽略」。App 不会退回明文。
</Aside>

## 技术细节

算法是 AES-256-GCM，每次使用随机的 12 字节 IV。密文格式为 `ob1.<keyId>.<iv>.<密文>`。口令用 PBKDF2-SHA256 迭代 60 万次，派生出 `obk1_` 密钥，只保存派生出的密钥，不保存那句话。

设计取舍见 [ADR 0007：端到端加密](/docs/adr/0007-end-to-end-encryption/) 和 [ADR 0006：服务端只做中转](/docs/adr/0006-relay-without-login-or-history/)。
